事件循环，与 JS 的单线程进制有关。最初作为脚本的 JS，主要操作对象是 HTML 的 DOM 元素，如果是多线程就会发生同一时间修改同一元素的冲突情况，因而单线程是最适合的。然而，有些代码执行时间很长或执行时间不确定，例如 HTML 元素的 click 事件处理函数。如果按顺序等待执行完成，会一直阻塞线程。于是，JS 把这部分归为异步事件，并利用一套循环进制来进行处理，这便是事件循环。

## 循环机制

首先，整段代码会从上往下，从左往右按顺序执行。执行时，如果遇到异步事件，会由宿主丢给对应类型的线程处理。其他线程会在触发条件后，会把回调函数放进一个队列中。JS 线程执行整段代码后，在空闲时轮询队列中是否有任务，有的话会取出来执行。这便是事件循环的机制。

### 单线程/多线程

虽然 JS 是单线程执行，但宿主环境会开辟其他线程来辅助执行。例如 setTimeout 是异步事件，调用时会把回调函数和相关信息，传递给处理该类型的另一线程。。

## 事件队列

事件队列并不是只有一种，为什么要有多种队列？这是由于事件也是需要优先级的，敏感型事件当然希望越快执行越好，部分事件不着急可以往后执行。常说的事件队列主要有两种类型：

### 宏任务队列

宏任务队列（Macrotask Queue），这是主要的队列，例如：

- 整体代码脚本
- setTimeout 和 setInterval 回调函数
- 用户交产生的事件，如点击事件、键盘事件等
- 浏览器的渲染事件

### 微任务队列

微任务队列（Microtask Queue），另一种优先级的队列，例如：

- Promise 的 then 方法回调
- MutationObserver 的回调
- queueMicrotask 方法添加的任务

## 事件周期

在一次循环周期中，宏任务队列会先开始执行，再检查微任务队列中的任务，然后不断循环。使用伪代码描述如下：

```js
while (true) {
  // 检查宏任务队列是否有任务
  if (macroTaskQueue.length > 0) {
    // 取出并执行宏任务队列中的第一个任务
    const macroTask = macroTaskQueue.shift();
    macroTask();
  }

  // 检查微任务队列是否有任务
  if (microTaskQueue.length > 0) {
    // 取出并执行微任务队列中的所有任务
    while (microTaskQueue.length > 0) {
      const microTask = microTaskQueue.shift();
      microTask();
    }
  }
}
```

注意：整段代码本身就是一个宏任务。此外，如今事件队列已细化成很多种，不再是这两种而已。但大致过程不会变：在一次循环周期内，优先级高的队列优先执行，直到所有队列都清空完。

## 结语

了解完事件循环，基本上就能判断异步事件回调函数的执行事件。
